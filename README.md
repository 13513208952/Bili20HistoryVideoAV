# Bili20HistoryVideoAV

这是一个我借助common crawl 和 internet archive数据源收集的 bilibili官网首页出现过的av号。出于观感考虑，我进行了一些基于标题和关键词的简单过滤，同时由于采集技术有限，可能会有一些本不该出现的av号误入。

本仓库有结构化整理进度和以下文件
当前可用候选 `av_list.txt`、已确认失效记录 `lost.av_list.txt`、全量历史采集记录 `global_past_av_list.md`。

采集情况总的来说来自2019年和2020年的存档记录的av号数量远大于其他年份。不过根据观感来看，也是这两年比较好。

如果想要搭建自定义B站推流，这个项目的av号经过过滤和筛选，应该可以提供还可以的观感体验。

作为老av号集中收录，很大一部分视频已经失效，考虑到新浪云备份等其他项目仍然有提供恢复的可能性，我没有剔除，使用者可以自行分析处理。

21年及以后的B站视频环境出现明显恶化，并且逐渐积累和加剧，直到今天，所以如果我发现了合适的视频也会把其av/bv号加入记录，但是我不会再专门整理和收集。

由于成本有限，很多清理和整理工作就被放弃了。如果质量不合您意-为什么不去问问神奇的大肥鱼呢？

过滤说明
目前过滤结构较为复杂而且仍然需要不断扩充和更新，过滤的对象也比较复杂，建议自行查看对应文件。总的来说，我们会尽力过滤不适宜大量占用大众空间的视频。

由于过滤远未完成，目前av_list暂时处于尚未完成的半成品阶段，如果希望使用，建议使用采集年20年的两个源组合，所有结构化整理进度都是已经由当前过滤规则过滤过的，但是仍未完善。您不需要重复使用过滤规则进行过滤。

如果您是出于考古等目的，建议自行在common crawl和internet archive中采集真正的原始数据，我没有办法提供任何保证。

按 AV 号直接使用，例如 `av170001`。由于采集年份对象原因，基本没有bv号对象。

建议搭配项目https://github.com/13513208952/BiliClient 共同使用，该项目提供了自定义排除规则等功能，而且还提供了反重复推送、反鱼灾评论等额外功能，且支持直接导入经过结构化处理的av号列表文件。 （本项目的av_list.txt文件支持直接导入，结构化处理只需要保持每行一个av号排列即可）

本仓库不对视频内容的可用性、版权或适宜性作任何担保；仅提供历史 AV 号清单与筛选规则说明。
